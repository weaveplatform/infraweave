# 06: spacectl and other Spacelift clients

Checked against: docs read 2026-10-28; schema `b3255fe38f5e`; spacectl at `6bf167cb62a6`, pulumi-spacelift at `6abf8237cd1d`, backstage-plugins at `27d06658468a`, setup-spacectl at `a359d07b6b87`, spacelift-helm-charts at `4e02e1d22e73`, spacelift-operator at `341692ad7d56` (read on GitHub).

Research baseline: **2026-10-28**.

This report records what Spacelift's client tools send to the API: every
`spacectl` command and subcommand mapped to the GraphQL root fields it calls,
the flags and environment variables that change what it sends, and how it
authenticates, pages, polls and reports errors. It then covers the other
clients Spacelift publishes: the Pulumi provider, the Kubernetes operator and
worker-pool controller, the Backstage plugins, the `setup-spacectl` GitHub
Action and the Helm charts for workers. It ends with the capabilities an
infraweave CLI must offer to replace `spacectl`. Engineers designing
infraweave's CLI, its authentication endpoints and its compatibility tests
need it. The Terraform provider is in
[05](05-terraform-provider.md); the operations themselves are inventoried by
family in reports 03 and 04, and the run behaviour the commands drive is in
report 08.

Method:

1. The command tree and the operations were generated by a script that
   reads the Go source as text and never builds or runs it.
   - A command is a `cmd.Command` or `cli.Command` literal with a `Name`; its
     parent is the nearest enclosing named literal, or the literal that lists
     the function returning it.
   - The root fields a command sends are the top-level fields of every struct
     passed to `.Query(ctx, &x, ...)` or `.Mutate(ctx, &x, ...)` on the call
     graph reachable from the command's `Action`. A field's name is its
     `graphql:"..."` tag, or its Go name in lowerCamel when it has none. Only
     names that are `Query` or `Mutation` fields in the introspection snapshot
     count.
   - Calls are followed within the package, into imported spacectl packages
     (`pkg.Func(`), into methods declared in those packages (`.Method(`) and
     through generic instantiations (`helper[T](`).
   - Calls made through an interface (the `draw.Table` used by
     `workerpool watch` calls its data source's `Rows` method) are not
     followed by the script; the fact-check pass found them by reading.
2. The tables were then generated from that inventory by a second script,
   which also joins each root field to its route in `spacelift.openapi.yaml`, and
   enriched by reading the implementing code; the notes link to it.
3. A coverage check listed every command path from the source and found
   none missing from this report.

Static analysis over-reports branches: an operation listed for a command is
one the command can send, not one it always sends. The notes say when an
operation depends on a flag.

### 2.2 Start-up probe and version-gated commands

Every invocation first builds a session and sends `debugInfo { selfHostedVersion }`
**[S]** [main.go#L37](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/main.go#L37).
An empty `selfHostedVersion` means SaaS; a semver means Self-Hosted at that
version; a failure leaves the type unknown and prints a warning. The command
tree is then resolved against that result
**[S]** [cmd.go#L100](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/internal/cmd/cmd.go#L100):

| `EarliestVersion` | Command available on |
|---|---|
| `all` | SaaS and every Self-Hosted version |
| `latest` | SaaS only, until the next Self-Hosted release |
| a semver such as `2.5.0` | SaaS, or Self-Hosted at that version or later |
| (instance type unknown) | Only `all` variants are offered, so a user without working credentials sees no `latest` or semver-gated command **[S]** [cmd.go#L153](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/internal/cmd/cmd.go#L153) |

A command can carry several versioned implementations; the newest one the
instance supports wins. Section 3 lists each command's variants. The schema
describes `debugInfo` as not valid in SaaS **[G]** `Query.debugInfo`; spacectl
reads an empty `selfHostedVersion` as SaaS, so the probe relies on SaaS
answering with an empty value rather than an error **[I]** from `main.go`. `profile`,
`whoami`, `registry` and `version` are not version-gated.

### 2.3 Credentials and sessions

Credential sources, in the order the source tries them
**[S]** [new.go#L16](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/client/session/new.go#L16),
[from_environment.go#L87](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/client/session/from_environment.go#L87):

| Order | Source | Variables or file | Exchange |
|---|---|---|---|
| 1 | Environment: API token | `SPACELIFT_API_TOKEN` | None; the JWT is used as is. Its single `aud` claim is the endpoint unless one is given **[S]** [api_token.go#L34](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/client/session/api_token.go#L34) |
| 2 | Environment: API key | `SPACELIFT_API_KEY_ENDPOINT`, `SPACELIFT_API_KEY_ID`, `SPACELIFT_API_KEY_SECRET` | `apiKeyUser(id, secret) { jwt validUntil }` **[S]** [api_key.go#L59](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/client/session/api_key.go#L59) |
| 2a | Environment: OIDC API key | as 2, with `SPACELIFT_API_KEY_OIDC_PROVIDER=github-actions` and optional `SPACELIFT_API_KEY_OIDC_AUDIENCE` instead of the secret | Mints a GitHub Actions ID token (`ACTIONS_ID_TOKEN_REQUEST_URL`, `ACTIONS_ID_TOKEN_REQUEST_TOKEN`, audience defaulting to the endpoint host) and sends it as the `secret` of `apiKeyUser` **[S]** [oidc_provider.go#L23](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/client/session/oidc_provider.go#L23) |
| 3 | Environment: GitHub token | `SPACELIFT_API_KEY_ENDPOINT`, `SPACELIFT_API_GITHUB_TOKEN` | `oauthUser(token) { jwt validUntil }` **[S]** [github_token.go#L54](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/client/session/github_token.go#L54) |
| 4 | Current profile | `${SPACELIFT_CONFIG_DIR:-$HOME/.spacelift}/config.json` | By the stored credential type: API key, GitHub token or API token |

Rules around the order:

- `SPACELIFT_API_PREFERRED_METHOD` (`token`, `github` or `apikey`) tries only
  that method **[S]** [from_environment.go#L76](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/client/session/from_environment.go#L76).
- `SPACELIFT_PROFILE` names a profile for the process and skips the
  environment credentials entirely **[S]** [profile_manager.go#L28](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/client/session/profile_manager.go#L28).
- `SPACELIFT_API_ENDPOINT` is still read when `SPACELIFT_API_KEY_ENDPOINT`
  is unset, with a deprecation warning.
- The docs give the environment order as API token, then GitHub token, then
  API key **[D]** <https://docs.spacelift.io/concepts/spacectl>. The source
  at the pinned commit tries the API key before the GitHub token. The docs
  rank higher as a source, but they describe the CLI, and the CLI's own code
  is what runs; both are recorded, and the difference only matters when both
  sets of variables are present.
- The OIDC variables need spacectl v1.28.0 or later and the job permission
  `id-token: write` **[D]** <https://docs.spacelift.io/integrations/api>.
  spacectl mints a fresh ID token for every exchange, so a job outlives the
  five-minute GitHub token **[D]** same page.

Token lifetime **[S]** [api_token.go#L18](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/client/session/api_token.go#L18),
[api_key.go#L43](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/client/session/api_key.go#L43):

- `apiKeyUser` and `oauthUser` return the `User` type's `jwt` and
  `validUntil` (Unix seconds) **[G]** `User`.
- Before each request an API-key or GitHub session re-exchanges when fewer
  than 30 seconds of validity remain.
- An API-token session cannot renew: it keeps sending the JWT until the
  server rejects it. `profile export-token` and `registry credentials`
  refuse an expired stored token up front **[S]**
  [from_profile_or_environment.go#L35](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/client/session/from_profile_or_environment.go#L35).

The docs and the source disagree on the profile layout. The source at the
pinned commit holds every profile in one `config.json`; the docs page still
describes per-alias files and a symlink. The source is what a reimplementation
must read if it imports existing profiles **[I]** from the two.

Browser login (`profile login --method browser`)
**[S]** [browserauth.go#L26](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/browserauth/browserauth.go#L26):

1. spacectl generates a 4096-bit RSA key pair and listens on
   `--bind-host`/`--bind` (`SPACECTL_BIND_HOST`, `SPACECTL_BIND_PORT`).
2. It opens `<endpoint>/cli_login?key=<base64url PEM public key>&port=<port>`
   (or prints it with `--no-browser`).
3. The browser comes back to the local listener with `token` and `key`
   query parameters. `key` is an AES key encrypted with RSA-OAEP (SHA-512);
   `token` is the JWT encrypted with AES-CBC under that key, the first block
   being the IV and the plaintext PKCS#7-padded; both values are unpadded
   base64url
   **[S]** [browserauth.go#L232](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/browserauth/browserauth.go#L232),
   [crypto.go#L50](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/internal/crypto.go#L50).
4. The listener redirects the browser to `/auth_success` or `/auth_failure`
   and stores an API-token profile. Requests that are not a callback get 404
   and do not end the login.

Since 2026-10-12 a `spacectl profile login` session is separate from the
browser session: it expires with the browser session it came from but
survives a browser logout **[RN]** <https://docs.spacelift.io/product/changelog>.
A token from `spacectl profile export-token` also authenticates the hosted
Spacelift MCP server, without the OAuth scope narrowing
**[D]** <https://docs.spacelift.io/concepts/intelligence/spacelift-mcp/connecting>.

### 2.4 Error behaviour

| Case | What spacectl sees | Evidence |
|---|---|---|
| HTTP status other than 200 on `/graphql` | Error `non-200 OK status code: <status> body: "<body>"` from the GraphQL client | **[S]** [spacelift-io/graphql v1.2.0 graphql.go#L92](https://github.com/spacelift-io/graphql/blob/87ff6fa23f4f/graphql.go#L92) |
| HTTP 200 with `errors` | `data` is decoded first, then the error is the first entry's `message`; `locations`, `path` and `extensions` are parsed but not shown | same file, L103 to L135 |
| Error text containing `unauthorized` | The check runs on the error string, so it matches a GraphQL error message or the body of a non-200 response alike. spacectl sends `viewer { id }`; if that succeeds the error becomes "logged in but maybe no access", otherwise "re-login with `spacectl profile login`" | **[S]** [client.go#L47](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/client/client.go#L47) |
| 401 on a non-GraphQL request (`Do`) | Error telling the user to log in again | **[S]** [client.go#L117](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/client/client.go#L117) |
| Token could not be obtained inside `Query` or `Mutate` | The call returns `nil` and the command carries on with an empty result | **[S]** [client.go#L27](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/client/client.go#L27) |
| `spacectl api` | Any 2xx body is printed; a body with `errors` also prints them to stderr and exits 1 | **[S]** [api.go#L104](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/internal/cmd/api/api.go#L104) |
| Missing entity | `stack(id)` that comes back null (detected as an ID mismatch) and null `module`/`stack.run` in the log explorer give spacectl's own "not found"; `runStack(runId)` for an unknown run instead returns a GraphQL error whose message is exactly `not found` | **[S]** [stack_selector.go#L139](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/internal/cmd/stack/stack_selector.go#L139), [#L157](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/internal/cmd/stack/stack_selector.go#L157); [explorer.go#L147](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/internal/logs/explorer.go#L147) |

So the client depends on these server contracts: authorization failures
carry the word `unauthorized` in the error text, and a missing or invisible
entity usually comes back as `null`, except `runStack`, which errors with
`not found` **[I]** from the handling above. The docs mirror names no rate
limit for the GraphQL API **[I]** from a search of the mirror. spacectl has
no rate-limit back-off; its only retry is a single resend after refreshing
the proxy token on a suspected proxy rejection, besides the polling loops in
section 5 **[S]** [proxy_auth.go#L355](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/client/proxy_auth.go#L355).

### 2.5 Stack resolution and the viewer fallback

Most `stack` commands accept `--id`, `--run` or neither
**[S]** [stack_selector.go#L44](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/internal/cmd/stack/stack_selector.go#L44).
The tables mark this resolution **+R**:

1. With `--id`, spacectl reads `stack(id)` to check the stack exists.
2. With `--run`, it reads `runStack(runId)` to find the run's stack.
3. With neither, it finds the Git repository root and the current
   subdirectory, then sends `searchStacks` with predicates `repository` (the
   repository name) and `projectRoot` (the subdirectory, with and without a
   trailing `/`), up to 50 results. It prompts even for a single match;
   `SPACECTL_SKIP_STACK_PROMPT=true` auto-selects a single match, but several
   matches still prompt
   **[S]** [stack_selector.go#L212](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/internal/cmd/stack/stack_selector.go#L212).
   An empty page triggers the same `viewer` check as **+V**. `local-preview`
   pages through every match with a 15 s limit and filters them
   **[S]** [stack_selector.go#L258](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/internal/cmd/stack/stack_selector.go#L258).

The tables mark **+V** where an empty `search…` page triggers `viewer` to tell
"nothing visible" from "not logged in".

## 5. Long-running and multi-step flows

### 5.1 Log streaming

`stack logs`, `module logs` and every `--tail` use one explorer
**[S]** [explorer.go#L79](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/internal/logs/explorer.go#L79):

1. Read `stack(id).run(id).history` (or `module(id).run(id).history`): the
   run's state transitions, each with `state`, `stateVersion`, `hasLogs` and
   `terminal`.
2. For each transition not yet reported, oldest first, print a banner and, if
   it has logs, page `run.logs(state, token, stateVersion)` until `finished`,
   or until `hasMore` is false for a terminal state. Each page returns
   `messages[].message`, `hasMore`, `finished`, `exists` and `nextToken`
   **[S]** [query.go#L66](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/internal/logs/query.go#L66).
3. Stop at a terminal transition. Without tailing, stop after this one pass:
   `stack logs` and `module logs` tail only with `--tail`, while `--tail` and
   `--auto-confirm` on other commands always tail
   **[S]** [explorer.go#L193](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/internal/logs/explorer.go#L193). When
   tailing, sleep and poll the history again. The sleep starts at 0 s, grows
   by 1 s per empty poll to a cap of 5 s, and resets when a new state appears.
   Each state is reported once, keyed by state name.
4. `--phase` prints only one state's logs and fails if the run ends without
   reaching it.

There is no subscription or server push; this is the contract a REST log
endpoint must reproduce: per-state logs addressed by `stateVersion`, an
opaque continuation token, and `hasMore`/`finished` flags
**[I]** from the loop above. Report 08 covers the states.

### 5.2 Auto-confirm

`stack deploy --auto-confirm` tails the run and, when a transition reaches
`UNCONFIRMED`, sends `runConfirm(stack, run)` with the same run-metadata
header **[S]** [run_trigger.go#L123](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/internal/cmd/stack/run_trigger.go#L123).

### 5.3 Local preview upload

1. `uploadLocalWorkspace(stack)` returns `LocalWorkspaceUpload { id uploadUrl uploadHeaders }` **[G]**.
2. spacectl writes a tar.gz to the temporary directory, honouring
   `.terraformignore` and `.gitignore`, and optionally including `.git`.
3. It `PUT`s the archive to `uploadUrl` with `Content-Length` and, on the variant
   gated at 2.5.0 (SaaS, or Self-Hosted 2.5.0+), the returned `uploadHeaders`
   **[S]** [local_preview.go#L183](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/internal/local_preview.go#L183).
4. `runProposeLocalWorkspace(stack, workspace: id, environmentVarsOverrides)`
   creates the proposed run; modules use `versionProposeLocalWorkspace`
   instead. `--project-root-only` packs only the stack's project root.

### 5.4 State download

`stateDownloadUrl(input: {stackId})` returns a presigned URL; spacectl `GET`s
it with a plain HTTP client, without the bearer token
**[S]** [state.go#L44](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/internal/cmd/stack/state.go#L44).
The field requires external state access on the stack **[G]**.

**[S]** [create_version.go#L22](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/internal/cmd/provider/create_version.go#L22):

## 8. What an infraweave CLI must cover

Capabilities, drawn from sections 2 to 7, that a replacement for `spacectl`
has to provide. These are requirements on coverage, not design choices.

| Area | Capability | Spacelift precedent |
|---|---|---|
| Credentials | Non-interactive credentials from the environment: a ready token, an API key exchanged for a short-lived token, an OIDC-backed key minted from the CI provider, and a method selector | section 2.3 |
| Credentials | Named profiles with a current selection and a per-process override, stored with restrictive permissions | `profile` |
| Credentials | Interactive browser login that never puts a long-lived secret on the command line | `profile login --method browser` |
| Credentials | Token export for other tools, and registry credentials for Terraform and OpenTofu (`TF_TOKEN_<host>` and `.terraformrc`) | `profile export-token`, `registry credentials` |
| Transport | Custom CA bundle, client certificates, a proxy-authentication hook, and client identification headers | section 2.1 |
| Compatibility | Detect the server's version and hide commands it cannot serve | section 2.2 |
| Errors | Distinguish "not logged in" from "not allowed", treat a missing entity as not found, and exit non-zero on any API error | section 2.4 |
| Stack targeting | Resolve a stack by ID, by run ID, or from the working directory's repository and project root, with a prompt that can be switched off | section 2.5 |
| Runs | Trigger tracked and proposed runs, tasks and local previews; confirm, discard, approve, reject, retry, stop, cancel, promote, replan targeted resources, set priority; attach run metadata | `stack` run commands |

## What this means for infraweave

- The CLI contract is wider than the GraphQL operations: it includes the
  token exchange, a session-version probe, presigned upload and download
  URLs with server-chosen headers, the run-metadata header, and a usage CSV
  endpoint. infraweave's REST API needs an equivalent for each (sections 2
  and 5).
- Log streaming is polled, keyed by run state and `stateVersion`, and paged
  with an opaque token. A REST log endpoint must offer the same addressing
  for a CLI to tail runs (section 5.1).
- Clients key behaviour off error text (`unauthorized`) and `null` results,
  not HTTP status. A REST API that uses 401, 403 and 404 changes those
  contracts; the plan must state how infraweave's CLI and any compatibility
  layer map them (section 2.4).
- Several published clients pin old or deprecated surfaces: the Pulumi
  provider bridges Terraform provider v1.9.3 and is itself deprecated, with
  its repository going read-only on 2026-12-10; spacectl still calls
  `runPrioritizeSet`, and the superseded
  `terraformProviderVersionRegisterPlatform` against Self-Hosted before 3.0.0;
  the archived operator calls the deprecated `policyCreate` and
  `policyUpdate`. Parity work must decide which of these to serve
  (sections 4 and 7).
- The Kubernetes worker-pool controller manages pools through the API with a
  dedicated system role and auto-registration; its calls are not public, so
  matching it needs captures (section 7.2).
- Section 8 lists the CLI capabilities the plan must place in phases.
