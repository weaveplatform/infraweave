The register holds every type of Spacelift's GraphQL schema, one record per type whose `id` is the type name, so other reports can cite a type, field or enum value without opening the snapshot. Descriptions are left out: they are Spacelift's prose and carry no stated licence. Report [28](28-data-model.md) builds the entity model on this inventory.

## Reading the register

A record's `kind` is the GraphQL type kind. `OBJECT` and `INTERFACE` records list their `fields` in upstream order, each with its `args`, its `type` in SDL notation such as `[String!]!`, whether it is `nullable`, and `deprecated` with the `deprecationReason` upstream gives, if any; `implements` and `implementedBy` link interfaces and the types that implement them. `INPUT_OBJECT` records list `fields` with their `default` and no deprecation, because the snapshot's introspection query does not ask for input field deprecation. `ENUM` records list `values`, `UNION` records list `members`, and `SCALAR` records hold only the name. Root queries and mutations are the fields of the `Query` and `Mutation` records. Records run in the order of the summary below, by name within a kind.
