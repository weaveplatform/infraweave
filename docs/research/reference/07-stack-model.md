## 1. What a stack is

A stack binds three things: source code at a repository, branch and project
root; the state of the infrastructure that code manages; and configuration,
meaning environment variables, mounted files, hooks and attachments. Each stack
is isolated from the others
[D](https://docs.spacelift.io/concepts/stack). Its state in the stack list
follows its most recent tracked run, and it is `NONE` while it has no runs
[D](https://docs.spacelift.io/concepts/stack) [G].

| Concept | Where it lives | Notes |
|---|---|---|
| Identity | `Stack.id: ID!`, the slug | Unique within an account and immutable; generated from the name at creation, or taken from the `slug` argument of `stackCreate` [G]. `stackReslug(id)` regenerates it from the current name, and the schema warns that Terraform resources referring to the old ID will be recreated [G]. |
| Home space | `Stack.space: ID!` | Written through `StackInput.space` [G]. |
| Vendor | the concrete type of `Stack.vendorConfig` (union `StackConfigVendor`) | There is no `vendor` field on `Stack`; see [typing traps](#9-typing-traps) [G]. |
| Source | `provider`, `vcsIntegrationId`, `namespace`, `repository`, `repositoryURL`, `branch`, `projectRoot`, `additionalProjectGlobs`, `gitSparseCheckoutPaths` | VCS behaviour is report 11. |
| State | `managesStateFile: Boolean!`, set once by `stackCreate(manageState:)` | Report 16. |
| Current state | `state: StackState!`, `stateIsTerminal`, `stateSetAt`, `stateSetBy` | See [section 6](#6-stack-state). |
| Run blocker | `blocked: Boolean!`, `blocker: Run` | The run holding the stack's run lock; distinct from the user lock in [section 5](#5-lock-and-unlock-enable-and-disable) [G]. |
| User lock | `lockedAt: Int`, `lockedBy: String`, `lockNote: String` | [G] |
| Enabled flag | `isDisabled: Boolean!` | [G] |

The mutations that create and change stacks are [G]:

| Mutation | Arguments | Returns | Purpose |
|---|---|---|---|
| `stackCreate` | `input: StackInput!`, `manageState: Boolean!`, `stackObjectID: String`, `slug: String` | `Stack!` | Create. `stackObjectID` names an uploaded state file to hand over (report 16). |
| `stackUpdate` | `id: ID!`, `input: StackInput!` | `Stack!` | Update; the whole `StackInput` is sent, with `name`, `branch` and `repository` required. |
| `stackDelete` | `id: ID!`, `destroyResources: Boolean` | `Stack` | Delete, optionally destroying resources first. |
| `stackReslug` | `id: ID!` | `Stack!` | Regenerate the slug from the name. |
| `stackLock` | `id: ID!`, `note: String` | `Stack!` | Lock for exclusive use. |
| `stackUnlock` | `id: ID!` | `Stack!` | Release the lock. |
| `stackEnable` | `id: ID!` | `Stack!` | Enable a disabled stack. |
| `stackDisable` | `id: ID!` | `Stack!` | Disable, so no new runs are created. |
| `stackSetCurrentCommit` | `id: ID!`, `sha: String!` | `Stack!` | Set the tracked commit used for tasks and, by default, tracked runs. |
| `stackSyncCommit` | `id: ID!` | `Stack!` | Sync the tracked commit to the branch head. |
| `stackMigrateVendor` | `id: ID!`, `targetVendor: StackVendor!`, `config: StackVendorMigrationInput` | `Stack!` | Move between a Terraform stack labelled `terragrunt` and native Terragrunt, in either direction. |
| `stackMigrateVendorAll` | `targetVendor: StackVendor!`, `config: StackVendorMigrationInput` | `StackMigrateVendorAllResult!` | The same for every eligible stack, under a time limit; returns `migrated` and `left` counts. |
| `openTofuMigrate` | `input: SearchInput!`, `target: StackVendor!`, `triggerRun: Boolean` | `OpenTofuMigrateResult!` | Asynchronously queue migration (target `OpenTofu`) or rollback of matching stacks between Terraform with the OpenTofu workflow tool and native OpenTofu. |
| `stackCreateFromIntent` | `project: ID!`, `importState: Boolean`, `stackName: String` | `Stack!` | Create from an Intent project (report 22). |
| `stackConfigAdd` / `stackConfigDelete` | `stack: ID!`, `config: ConfigInput!` / `stack: ID!`, `id: ID!` | `ConfigElement!` / `ConfigElement` | Environment variables and mounted files (report 13). |

The REST projection serves these at `POST /stacks`, `PUT`/`DELETE /stacks/{stackId}`,
and `POST /stacks/{stackId}/lock`, `/unlock`, `/enable`, `/disable`, among others
([`spacelift.openapi.yaml`](../../../api/reference/spacelift/spacelift.openapi.yaml)).
The Bruno collection carries requests for `stackCreate`, `stackUpdate`,
`stackLock`, `stackUnlock`, `stackEnable` and `stackDisable`; its `stackCreate`
example sends `manageState: false` and a minimal input of name, description,
space, repository, branch, project root, `administrative`, `autodeploy` and
labels [B].

Creating, updating, deleting and re-slugging a stack each need an Admin-level
action ("Create stack", "Update stack", "Delete stack", "Re-slug stack"), while
setting or syncing the tracked commit needs only Writer
[D](https://docs.spacelift.io/concepts/authorization/rbac-system).

### 2.4 Hooks

Eleven hook lists customise the workflow. Each is `[String!]` on `StackInput`;
`Stack` exposes the same lists both as deprecated flat fields and under
`hooks: Hooks!` [G]. `Context` also implements `Hookable`, so contexts carry
hooks too [G]. Each hook defaults to an empty list [D](https://docs.spacelift.io/concepts/configuration/runtime-configuration).

| Phase | Before field / TF attribute | After field / TF attribute |
|---|---|---|
| Initialization | `beforeInit` / `before_init` | `afterInit` / `after_init` |
| Planning | `beforePlan` / `before_plan` | `afterPlan` / `after_plan` |
| Applying | `beforeApply` / `before_apply` | `afterApply` / `after_apply` |
| Performing (tasks) | `beforePerform` / `before_perform` | `afterPerform` / `after_perform` |
| Destroying | `beforeDestroy` / `before_destroy` | `afterDestroy` / `after_destroy` |
| Finally (every processed run) | none | `afterRun` / `after_run` |

Behaviour that a stack setting must preserve [D](https://docs.spacelift.io/concepts/stack/stack-settings):
- the commands of a hook list are joined with `&&` and each is wrapped in braces, so a newline inside one entry can hide a failing command;
- a failing before-hook skips its phase; a failing phase skips its after-hooks, unless the hook uses `;`;
- hooks share the phase's shell session, so variables a hook exports are visible to the phase; a run that stops to wait for confirmation or approval resumes in a fresh container, so tools a hook installed earlier are gone;
- `after_run` sees `TF_VAR_spacelift_final_run_state`; no hook runs if the run ends outside the worker, for example when canceled or discarded;
- the destroy hooks are used by module test cases and by stack destruction through `spacelift_stack_destructor`;
- `.spacelift/config.yml` can override the hook lists ([section 7](#7-runtime-configuration-spaceliftconfigyml)).

Hooks from contexts are merged with stack hooks in a fixed order. Before a
phase: hooks of manually attached contexts by priority, then auto-attached
contexts in reverse alphabetical order, then the stack's own. After a phase:
the stack's own, then auto-attached contexts alphabetically, then manually
attached contexts in reverse priority order [D](https://docs.spacelift.io/concepts/stack/stack-settings).
Context priority itself is report 13. A hook can also emit the runtime command
`::add-mask <values>`, which masks each whitespace-separated value as five
asterisks in later log output [D](https://docs.spacelift.io/concepts/stack/stack-settings).

## 3. Vendor configuration

`StackVendor` has seven values: `Ansible`, `CloudFormation`, `Kubernetes`,
`Pulumi`, `OpenTofu`, `Terraform`, `Terragrunt` [G]. `StackConfigVendorInput`
has one field per vendor and only one may be set [G]. On read,
`Stack.vendorConfig` is the union `StackConfigVendor`, whose seven member types
mirror the inputs [G]. In the provider each non-Terraform vendor is a nested
block whose presence selects the vendor, the vendor blocks conflict with each
other and with the top-level Terraform attributes, and a stack with no vendor
block is a Terraform stack [S](https://github.com/spacelift-io/terraform-provider-spacelift/blob/c72b9bd2f3c3/spacelift/resource_stack.go#L1276).

The vendor is fixed at creation. An update that changes it is rejected with an
error saying the vendor cannot be changed after creation
[D](https://docs.spacelift.io/vendors/opentofu/migration). Only the migration
mutations in [section 1](#1-what-a-stack-is) change it.

### 3.1 Ansible

| Field | Input type | Output type | Default | Meaning | TF attribute |
|---|---|---|---|---|---|
| `playbook` | `String!` | `String!` | none, required | Playbook file to run [G] [D](https://docs.spacelift.io/vendors/ansible/reference). | `ansible.playbook` |

Planning runs Ansible in check mode. Environment variables change behaviour:
`SPACELIFT_SKIP_PLANNING=true` skips planning,
`SPACELIFT_IGNORE_SKIPPED_TASK_CHANGES=true` subtracts skipped tasks from the
change count so autodeploy can auto-confirm, `SPACELIFT_ANSIBLE_CLI_ARGS` and
its `_plan` and `_apply` variants add CLI flags, and
`SPACELIFT_ANSIBLE_REQUIREMENTS_FILE` moves `requirements.yml`
[D](https://docs.spacelift.io/vendors/ansible/reference).

### 3.8 Legacy Terragrunt and vendor migration

A Terraform stack with the `terragrunt` label runs `terragrunt` in place of
`terraform`. The label is deprecated and will be removed on 2026-10-31
[D](https://docs.spacelift.io/vendors/terraform/terragrunt).
`stackMigrateVendor` converts such a stack to native Terragrunt, optionally with
a `terragruntVersion`, and back to Terraform, where the provider sends the
`terragrunt` label in `StackVendorMigrationInput.labels`
[G] [S](https://github.com/spacelift-io/terraform-provider-spacelift/blob/c72b9bd2f3c3/spacelift/resource_stack.go#L1507).
The provider refuses a migration that would change whether state is managed
[S](https://github.com/spacelift-io/terraform-provider-spacelift/blob/c72b9bd2f3c3/spacelift/resource_stack.go#L77).
OpenTofu migration copies version, workspace, smart sanitization and external
state access, sets concise output and CPU profiling by version, skips stacks
with a run in progress until it finishes, excludes stacks labelled `terragrunt`,
needs Space Writer or Admin, and refuses machine-user API keys
[D](https://docs.spacelift.io/vendors/opentofu/migration).

### 5.1 User lock

| Aspect | Behaviour | Source |
|---|---|---|
| Who locks | Any stack writer (`STACK_LOCK`), unless already locked. | [D](https://docs.spacelift.io/concepts/stack/creating-a-stack) [D](https://docs.spacelift.io/concepts/authorization/rbac-system) |
| Note | Optional `note` on `stackLock`; read back as `lockNote`. | [G] [S](https://github.com/spacelift-io/spacectl/blob/6bf167cb62a6/internal/cmd/stack/lock.go#L13) |
| Effect | Only the lock holder can trigger runs and tasks; autodeploy is suspended. | [D](https://docs.spacelift.io/concepts/stack/creating-a-stack) |
| Expiry | None. | [D](https://docs.spacelift.io/concepts/stack/creating-a-stack) |
| Unlock | `stackUnlock`: the holder needs `STACK_UNLOCK` (Writer); anyone else needs `STACK_UNLOCK_FORCE` (Admin). | Read model | `lockedAt` (Unix seconds), `lockedBy` (a username, not an ID), `lockNote`; the provider treats the stack as locked when `lockedAt` is set. | [G] [S](https://github.com/spacelift-io/terraform-provider-spacelift/blob/c72b9bd2f3c3/spacelift/internal/structs/stack.go#L147) |
| Provider guard | `prevent_changes_when_locked` makes the provider fail a plan that changes a locked stack, and fail destroy at apply time. | [S](https://github.com/spacelift-io/terraform-provider-spacelift/blob/c72b9bd2f3c3/spacelift/resource_stack.go#L58) [S](https://github.com/spacelift-io/terraform-provider-spacelift/blob/c72b9bd2f3c3/spacelift/resource_stack.go#L1075) |

The user lock is not the run lock. The run lock is held by the run in
`Stack.blocker`, with `Stack.blocked` set, and it is what queued runs wait for
[G]; report 08 covers it. Managed state workspaces have a third lock, with
`STACK_WORKSPACE_LOCK` and `STACK_WORKSPACE_UNLOCK` (report 16)
[D](https://docs.spacelift.io/concepts/authorization/rbac-system).

### 5.2 Enable and disable

`stackDisable` and `stackEnable` each need an Admin-level action
(`STACK_DISABLE`, `STACK_ENABLE`) [G] [D](https://docs.spacelift.io/concepts/authorization/rbac-system).
A disabled stack cannot create runs, and `isDisabled` reports it [G]. The
provider manages the flag through `spacelift_stack_activator`, which reads
`isDisabled` and calls the matching mutation only when it differs
[S](https://github.com/spacelift-io/terraform-provider-spacelift/blob/c72b9bd2f3c3/spacelift/resource_stack_activator.go).
`StackInput.isDisabled` also writes it [G]. What happens to runs already queued
when a stack is disabled is not documented *(unverified)*.

### 5.3 Deletion

`stackDelete` is asynchronous: the result can carry `deleting: true` while
removal continues, and the provider polls until the stack is gone
[S](https://github.com/spacelift-io/terraform-provider-spacelift/blob/c72b9bd2f3c3/spacelift/resource_stack.go#L1094).
`destroyResources` asks for the managed resources to be destroyed first, which
native Terragrunt does not support [G] [D](https://docs.spacelift.io/concepts/stack/creating-a-stack).
`protectFromDeletion` blocks deletion [S]. Deleting a stack needs the Admin-level "Delete stack" action
[D](https://docs.spacelift.io/concepts/authorization/rbac-system). Separately from `destroyResources`, the docs list a
per-vendor command to run as a task before deletion (`terraform destroy -auto-approve`, `tofu destroy -auto-approve`,
`aws cloudformation delete-stack`, `pulumi destroy --non-interactive --yes`, and a label-selected `kubectl delete`)
[D](https://docs.spacelift.io/concepts/stack/creating-a-stack). Scheduled deletion is report 18.

## 6. Stack state

`StackState` has 16 values [G]. It equals `RunState` minus `UNKNOWN`, `QUEUED`,
`CANCELED`, `PERFORMING`, `SKIPPED`, `PENDING` and `PENDING_REVIEW`, plus `NONE`
[G], because it reflects only the current or last tracked run (and destroy
jobs), not tasks or proposed runs [I: from the value descriptions].

| Value | Meaning [G] |
|---|---|
| `NONE` | No tracked run yet. |
| `INITIALIZING`, `PLANNING`, `PREPARING`, `PREPARING_APPLY`, `PREPARING_REPLAN`, `READY`, `APPLYING`, `CONFIRMED`, `UNCONFIRMED`, `REPLAN_REQUESTED` | The current tracked run is in that state. |
| `DESTROYING` | A destroy job is deleting managed resources. |
| `FINISHED`, `FAILED`, `DISCARDED`, `STOPPED` | The last tracked run ended in that state. |

`stateIsTerminal` is true when no run is ongoing; `stateSetBy` is the run that
last set the state [G]. The UI's predefined tabs group `UNCONFIRMED` as
needing attention, `FAILED` as failed, `NONE`, `CONFIRMED` and `REPLAN_REQUESTED` as on hold,
`APPLYING`, `DESTROYING`, `INITIALIZING`, `PLANNING`, `PREPARING_APPLY` and `PREPARING_REPLAN` as in progress,
and `FINISHED` as finished; `PREPARING`, `READY`, `DISCARDED` and `STOPPED` sit in no tab
[D](https://docs.spacelift.io/concepts/stack/organizing-stacks).

## 7. Runtime configuration: `.spacelift/config.yml`

### 7.1 File and structure

The file sits at the repository root, not the project root, and configures
every stack (and module) that uses the repository
[D](https://docs.spacelift.io/concepts/configuration/runtime-configuration/runtime-yaml-reference).
It is read per run, so a change on a feature branch shows up in that branch's
proposed runs before it can affect state
[D](https://docs.spacelift.io/concepts/configuration/runtime-configuration).
The effective result is stored on each run as `Run.runtimeConfig: RuntimeConfig`,
including the raw `yaml` [G].

| Top-level key | Type | Meaning |
|---|---|---|
| `version` | string | `"2"` selects the current precedence; absent means `1` [D](https://docs.spacelift.io/concepts/configuration/runtime-configuration). The YAML reference instead says the key is optional and ignored [D](https://docs.spacelift.io/concepts/configuration/runtime-configuration/runtime-yaml-reference); which holds is *(unverified)*. |
| `stack_defaults` | map | Settings for every stack using the repository. |
| `stacks` | map of stack slug to settings | Per-stack settings; a stack value replaces the default outright, including lists and maps; merging needs YAML anchors and merge keys [D](https://docs.spacelift.io/concepts/configuration/runtime-configuration/runtime-yaml-reference). |
| `module_version` | string | Module repositories: required plain `major.minor.patch` (report 15). |
| `test_defaults`, `tests` | map; list | Module test cases: `name` (required), `negative`, `id`, `depends_on` (report 15). |

When `spacectl stack deploy --runtime-config` supplies a file, it contains a
single stack's settings without the top-level keys
[D](https://docs.spacelift.io/concepts/configuration/runtime-configuration). Such
a per-run override travels as `runTrigger(runtimeConfig: RuntimeConfigInput)`,
needs the Admin-level "Trigger run with custom runtime config" action, and is
kept as `Run.customRuntimeConfig` [G] [D](https://docs.spacelift.io/concepts/authorization/rbac-system).
`RuntimeConfigInput` takes either `yaml` or the individual fields, never both;
its fields are `environment` (`[EnvVarInput!]`), `projectRoot`, `runnerImage`,
the eleven hooks and `gitSparseCheckoutPaths` [G].

### 7.2 Precedence against stack settings

With version 2, from strongest to weakest
[D](https://docs.spacelift.io/concepts/configuration/runtime-configuration):
1. the stack's entry under `stacks`;
2. `stack_defaults`;
3. the stack's own settings.

With version 1, stack settings beat `stack_defaults`. The same page then says
that, when the file has no entry for the stack, the stack's settings come before
`stack_defaults`; this contradicts the version 2 rule and is recorded as
*(unverified)*. The label `feature:ignore_runtime_config` drops the file
entirely [D](https://docs.spacelift.io/concepts/stack/stack-settings).

| `opentofu_version` | string | latest supported | the version of a Terraform stack with workflow tool `OPEN_TOFU` | Not read by native OpenTofu stacks. |
| `opentofu` | map: `version`, `workflow_tool` | `workflow_tool: OPENTOFU` | OpenTofu `version` and `workflowTool` | Without `version` the run uses the newest supported OpenTofu, not the stack's; `version` is ignored with `CUSTOM`. Other OpenTofu settings cannot be overridden. Lookup stops at the first level (stack, then defaults) that has an `opentofu` block. A native OpenTofu stack whose applicable level sets `terraform_version` or `opentofu_version` without an `opentofu` block fails every run during preparation [D](https://docs.spacelift.io/concepts/configuration/runtime-configuration) [D](https://docs.spacelift.io/vendors/opentofu). |
| `terraform_workflow_tool` | `TERRAFORM_FOSS` or `CUSTOM` | `TERRAFORM_FOSS` | Terraform `workflowTool` | |
| `git_sparse_checkout_paths` | list of strings | empty, meaning the stack's value applies | `gitSparseCheckoutPaths` | Paths only. |
| `terragrunt` | map: `terragrunt_tool`, `terragrunt_version`, `terraform_version`, `use_run_all`, `use_smart_sanitization`, `use_state_management` | each field's own default | the Terragrunt vendor settings | Replaces every Terragrunt value rather than merging, so unset fields return to defaults; has no effect on other vendors. |

The YAML reference's `stack_defaults` table lists only the hooks,
`environment`, `project_root`, `runner_image` and `terraform_version`, while the
runtime configuration page also documents `opentofu_version`, `opentofu`,
`terraform_workflow_tool`, `git_sparse_checkout_paths` and `terragrunt`
[D](https://docs.spacelift.io/concepts/configuration/runtime-configuration/runtime-yaml-reference)
[D](https://docs.spacelift.io/concepts/configuration/runtime-configuration).
The read model `RuntimeConfig` has the hooks, `environment`, `projectRoot`,
`runnerImage`, `terraformVersion`, `terraformWorkflowTool`,
`gitSparseCheckoutPaths`, `yaml`, and per-vendor `terraform`, `opentofu` and
`terragrunt` objects [G]. Whether unknown keys are rejected or ignored is not
documented *(unverified)*.

## 8. What the read model adds

`Stack` has 121 fields [G]. Beyond the settings above, the ones that bear on the
model are: `deleted`, `deleting`; `trackedCommit`, `trackedBranchHead`,
`trackedCommitSetBy`; `vcsDetached` and `vcsIntegration`;
`isLockedByTemplateDeployment` (a stack managed by an active template deployment
is read-only, report 17); `blueprint` and `templateDeployment`;
`wasMigratedFromTerraform`; `isDrifted` and `driftDetectedBy`;
`isStateRollback`; `needsApproval`; `runtimeConfig`, the computed list of
configuration elements from contexts, the stack and integrations; and
`allowedActions`, the caller's per-action permissions [G].

## 9. Typing traps

| Trap | Detail | Source |
|---|---|---|
| No vendor field | `Stack` has no `vendor`; clients read `vendorConfig { __typename }` and map `StackConfigVendorOpenTofu` and the others. `ManagedEntity.stackVendor` does use the `StackVendor` enum. | [G] [S](https://github.com/spacelift-io/terraform-provider-spacelift/blob/c72b9bd2f3c3/spacelift/internal/structs/stack.go#L94) |
| Enum spelling | `StackVendor` values are PascalCase (`OpenTofu`); `TerraformWorkflowTool` and `TerragruntTool` spell OpenTofu `OPEN_TOFU`; `OpenTofuWorkflowTool` spells it `OPENTOFU`. | [G] |
| Hooks shape | Input hooks are flat fields on `StackInput`; output hooks are nested in `Stack.hooks`, with the flat output fields deprecated. | [G] |
| Promotion name | "Allow run promotion" is `githubActionDeploy` in GraphQL and `allow_run_promotion` (or deprecated `github_action_deploy`) in Terraform. | [G] [S] |
| State management outside the input | `manageState` and `stackObjectID` are `stackCreate` arguments, not `StackInput` fields, and the read-back is `managesStateFile`; Terragrunt also has `useStateManagement` inside its vendor input. | [G] |
| Two Terraform versions | `StackInput.terraformVersion` overrides `vendorConfig.terraform.version`; `Stack.terraformVersion` is overwritten with the applied version after an apply. | [G] [D](https://docs.spacelift.io/vendors/terraform/version-management) |
| Required but empty | Kubernetes `namespace` is `String!` but an empty string means all namespaces. | [G] [S] |
| Nullability flips | `kubectlVersion`, `kubernetesWorkflowTool`, every `workflowTool`, `tool`, and most booleans are nullable on input and non-null on output; Terragrunt `useRunAll` and `useSmartSanitization` are non-null on input, unlike the other vendors' booleans. | [G] |
| Version-dependent defaults | OpenTofu `concise` and `enableCPUProfiling` default by the lowest version a constraint admits when unset at creation. | [G] [D](https://docs.spacelift.io/vendors/opentofu) |
| Conflicting Terragrunt default | `tool` defaults to `TERRAFORM_FOSS` in the schema and provider but to `OPEN_TOFU` in the UI. The schema is the higher source for the API; the UI default is a product fact for new stacks created there. | [G] [S] [RN] |
| Full-object update | `stackUpdate` takes a whole `StackInput` with `name`, `branch` and `repository` required. Whether an omitted optional field keeps or resets its value is not documented; the provider always sends every hook list and never sends `isDisabled`, `skipVendorBinaryDownload` or the top-level `terraformVersion`. *(unverified)* | [G] [S](https://github.com/spacelift-io/terraform-provider-spacelift/blob/c72b9bd2f3c3/spacelift/resource_stack.go#L1105) |
| Timestamps | `createdAt`, `lockedAt`, `stateSetAt` and `lastApplyAt` are `Int` Unix seconds; `runsInRange` takes them as strings and allows at most 8 days. | [G] |
| Lock holder | `lockedBy` is a username string. | [G] |
| Public pool | A null `workerPool` means the shared public pool. | [G] |
| Ineffective field | `administrative` is still accepted and ignored. | [G] [D](https://docs.spacelift.io/concepts/stack/stack-settings) |
| Labels | A list in GraphQL, a set in Terraform, unique per stack in the docs. | [G] [S] [D](https://docs.spacelift.io/concepts/stack/stack-settings) |
| Disabled actions | `Action` values `STACK_CONTEXT_ATTACH`, `STACK_POLICY_ATTACH` and the other stack attach, integration, role-binding and webhook actions are marked "Disabled. Do not use." | [G] |
| Runtime YAML types | `environment` is a map of strings in YAML but a list of `{key, value}` in `RuntimeConfigInput`; `version` is the string `"2"`. | [G] [D](https://docs.spacelift.io/concepts/configuration/runtime-configuration) |

## What this means for infraweave

- The stack resource needs every `StackInput` field in section 2, the
  `manageState`, `stackObjectID` and `slug` creation arguments, and the seven
  vendor configurations, with one vendor per stack, fixed at creation except
  through explicit migration operations.
- Slugs are generated from names, immutable, and changed only by a reslug
  operation; clients and the runtime YAML key on them.
- The user lock, the run lock and state workspace locks are three separate
  mechanisms with different permissions.
- Labels carry behaviour: auto-attachment of contexts, policies, integrations
  and plugins, UI folders, and the `feature:` and `ghenv:` switches. The plan
  must decide which switches become real settings.
- Run preparation must resolve `.spacelift/config.yml` with version-dependent
  precedence, whole-value replacement for stack entries, the `opentofu` block
  rules and the `terragrunt` replace-not-merge rule, and record the result on
  the run.
- Defaults differ between the schema, the provider and the UI (Terragrunt tool,
  run promotion, OpenTofu defaults by version); the API contract must state its
  own.
- Update semantics for omitted fields must be defined, since Spacelift's are not
  documented.

## Inferred and undocumented

- `isDisabled` and `skipVendorBinaryDownload` default to `false` [I: neither
  the provider nor the UI sets them, and new stacks run normally].
- `stackUnlock` decides between a normal and a forced unlock from the caller's
  permissions [I: the schema has no force argument and RBAC has
  `STACK_UNLOCK_FORCE`].
- `StackState` excludes the task and proposed-run states because it reflects
  tracked runs only [I: from the value descriptions].
- Open: label length and character rules; queued runs on disable; omitted-field
  semantics of `stackUpdate`; whether runtime hooks replace context hooks;
  unknown runtime YAML keys; the `version` key contradiction and the no-entry
  precedence sentence. Each is marked *(unverified)* above and listed for
  30-open-questions.
